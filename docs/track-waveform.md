# Complete-track seek waveforms

`utils/audio/track-waveform.ts` exports `decodeTrackWaveform(trackId, { signal?, onProgress? })` for the local library and `decodeWaveformBlob(blob, options)` for offline verification. Both dynamically import the same unmodified Mediabunny 1.61.6 decoder used by the original analysis utility. [Dependency attribution and license](audio-analysis.md) apply to both APIs.

The result contains `complete: true` only after the audio sample iterator reaches the end of the track. It includes `trackId`, `source: 'mediabunny'`, actual `durationSeconds`, codec/sample-rate/channel information, decoded frame and received-byte counts, aggregate linear-amplitude `peak`/`rms`, and at most 256 bins. Each bin contains its actual `startSeconds`, `endSeconds`, `peak`, and `rms`. There is no partial-waveform result on cancellation, detected truncation, malformed data, missing codec support, or a resource limit. Completion describes the available decoded timeline; it cannot establish whether a valid short compressed file was cut from a longer original before import.

The accumulator starts with short time intervals and merges adjacent pairs when it needs more timeline space. Peak is the maximum observed amplitude; RMS is recomputed from summed squares and actual channel-sample counts. This retains both quiet and loud sections without normalizing the graph or averaging opposite stereo phases into silence. It stores about 5 KiB of bin aggregates rather than the decoded track. The final result usually has 129–256 bins, but very short files may have fewer. The last interval can be shorter than its neighbors.

Place bars by their explicit timestamps on the seek timeline, with any final codec-padding tail clipped to the native player's duration. Do not assign equal widths when the final bin is shorter, stretch a 30-second preview, or use the waveform as a second independent drag control. The native range input remains the accessible seek control. If native playback duration materially differs from the decoded duration, retain the plain seek rail. Small encoder-delay/padding differences are normal: the 12-second MP3 fixtures decode to 12.04244898 seconds. The module rejects container-metadata disagreements greater than 0.25 seconds in either direction.

Progress has `phase: 'opening' | 'decoding'`, `decodedSeconds`, `totalSeconds: number | null`, and `receivedBytes`. The total is only a container estimate until completion. Progress never includes partially complete waveform bins. Errors use the existing `AudioAnalysisError` codes: `cancelled`, `busy`, `unsupported`, `network`, `invalid-audio`, `limit`, and `timeout`. All are ordinary reasons to preserve the working plain seek bar.

## Background-work limits

- Complete decoded timeline at most 10 minutes, 60 million channel samples, 8 channels, and 96 kHz. Metadata allows early rejection; actual sample processing independently enforces the bounds when metadata is missing or misleading. Every native channel sample counts, including negative-timestamp priming trimmed before time zero, and native timestamps must remain monotonic.
- A 15-second wall-time budget, 16 MiB received-body stop threshold, 16 MiB compressed source cache, one range request at a time, and no automatic network retries. The source retains every compressed byte that fits the existing download ceiling: container probes must not evict early Ogg packets and force repeated downloads during decoding. The incoming chunk that crosses the body threshold may already have arrived; browser/native buffers exist outside the JavaScript copy budget.
- At most 16,384 frames in each copied PCM block, 1,048,576 frames per yielded native sample, and 100,000 yielded samples. Reduction yields to the event loop at roughly 8 ms intervals, including samples trimmed outside the nonnegative timeline. A timer cannot interrupt synchronous native decoder work already executing.
- One full-waveform request at a time. Aborting synchronously disposes the old input; an immediate replacement can start while an obsolete codec promise unwinds. An old completion cannot clear the replacement's ownership or publish progress.
- Only validated local track IDs and their same-origin `/stream` endpoint are accepted. Redirects and alternate URLs are rejected. The UI skips external podcast episodes entirely, cancels when the track, eligibility or owning layout changes, and publishes only the current request's result. Closing the full player retains the current layout's work so the persistent seek bar can use it. The layout keeps up to eight successful results; failures and cancellations are retried on a later selection. This utility never changes native playback, the queue, or the player store.

RIFF/WAVE files receive an additional bounded prefix check before decoding: the declared RIFF size and first audio-data chunk must fit the actual file extent. This catches genuinely truncated WAVE headers even when the media library normalizes their duration to available bytes. The inspection reads at most 64 KiB; unusually large WAVE headers, unavailable file sizes, RF64, and big-endian RIFX conservatively use the plain seek fallback. Compressed formats rely on the decoder's EOF/error handling and the duration cross-check; they do not have an invented universal file-integrity guarantee.

## Evidence

The 19 focused accumulator and integration tests use the real Mediabunny PCM decoder. An original 65-second WAV is silent for the first minute and has its only signal from 61–63 seconds. The resulting bins place that signal at 61–63 seconds, with all first-30-second bins zero. An actual 600-second PCM stream completes within 150 bins; a 601-second stream is rejected with and without duration metadata. Additional tests cover exact weighted RMS after adaptive merging, silence/antiphase stereo, actual malformed RIFF/data extents in Blob and HTTP bodies, excessive negative-timestamp native samples, erroneous duration metadata, capability/size failures, timeout, cancellation, and a late old codec promise after an immediate replacement.

`pnpm test:audio-codecs` also exercises the production full-waveform API in standalone Chromium through native `AudioDecoder`, with no application server. Both licensed 12-second MP3 fixtures produce 193 bins and retain the independently verified FFmpeg amplitude levels. An original 65-second PCM signal encoded to MP3 produces a complete 65.088-second timeline with 131 bins; the only audible bins remain at 61–63.5 seconds, including codec tail. One measured Chromium 156 run completed that decode in approximately 108 ms; this is a local observation, not a cross-device performance guarantee. The report is `.test-data/audio-analysis/real-codec-report.json`.

Application browser proof of the integrated seek control is a separate gate from these decoder checks.

### Long Ogg range regression

`node scripts/verify-waveform-ranges.mjs` creates original seeded white noise with FFmpeg, encodes a three-minute stereo Ogg, and serves it through a loopback-only range endpoint to the production decoder in Chromium. It checks complete duration, actual received bytes equal to the full compressed file, bounded bins, and absence of unexpected errors. The generated audio and evidence remain ignored under `.test-data/waveform-ranges`. One Chromium 156 run decoded 8,889,221 bytes into a 180.001-second waveform in 750 ms. With `--negative-control`, the diagnostic bundle restores the former 2 MiB cache and the same completion assertion fails with `code: limit`; production source is unchanged by that control.

The issue was found with a private 411-second Ogg: its 9.24 MB compressed file fit the network limit, but early packets were evicted during container probing and counted again when reread. The corrected cache completed it in approximately two seconds with exactly 9,240,860 received bytes. This is local performance evidence, not a cross-device timing guarantee. No private audio is part of the committed regression.

### Completed-range cleanup

Mediabunny 1.61.6 deliberately aborts a `UrlSource` request once its worker has received its target byte range, before another stream read necessarily observes HTTP EOF (`node_modules/mediabunny/src/source.ts:1066–1071`). Disposing the input also aborts remaining readers (`source.ts:1296–1303`). Chromium can therefore report `net::ERR_ABORTED` for a consumed range even when the complete waveform succeeds.

A focused reproduction passed the real 91,726-byte `spoken-test.wav` fixture through the production `decodeTrackWaveform` function and actual PCM decoder. Only the fetch boundary was controlled: it delivered all bytes immediately and delayed HTTP EOF by 200 ms. The captured abort stack identified `UrlSource._runWorker` (installed compiled `source.js:743`); cancellation occurred after all bytes were delivered, and decoding returned `complete: true`, 2.864 seconds, 45,824 frames, 184 bins, and RMS 0.0979831283. Separately, the application browser trace showed one Distant Sun stream request and its matching ready waveform before queue actions.

This successful range cleanup differs from cancelling incomplete work on a track change, resource limit, or decode failure. A browser error guard may accept only an identified request's `ERR_ABORTED` when its successful 206 response and matching complete ready waveform are independently asserted. The tiny MP3 journey additionally requires a single request. Long Ogg journeys can open multiple range workers; every accepted request must have a valid 206 extent for that exact original file, and the decoder regression additionally proves that actual received bytes equal the entire file. Guards must retain other request failures and unexpected retries; a path-wide `/stream` exemption would hide real failures. Neither this exception nor decoded completion proves universal HTTP integrity or the original duration of a compressed file before import.
